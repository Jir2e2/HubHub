# Отчёт об аудите безопасности и код-ревью — HubHub

## 1. Безопасность

### Секреты
- Токен GitHub передаётся через переменную окружения `GITHUB_TOKEN`, никогда не хардкодится в коде.
- `.env` и `.env.example` занесены в `.gitignore` — секреты не попадают в коммиты.
- В Docker Compose переменные подставляются из окружения, не записываются в образы.

### SQL-инъекции
- Python: все запросы параметризированы через `cursor.execute(sql, params)`.
- C#: все запросы параметризированы через `MySqlCommand.Parameters.AddWithValue`.
- ORM не используется — прямые SQL-запросы, что исключает неявное экранирование ORM.

### Входная валидация
- GitHub токен проверяется на наличие перед запросами к API.
- Фильтры API (`search`, `domain`, `repo`, `date`) передаются параметризованно.
- URL нормализуются перед записью (удаление UTM-параметров, trailing slash).

### Транспорт
- Внутри Docker-сети связи между сервисами по HTTP. В продакшене рекомендуется TLS терминация на ингресе.

## 2. Код-ревью

### Python service (`app.py`)
- Обработка ошибок LLM: fallback на regex при недоступности LLM API.
- Проверка существования репозитория перед сканированием, 삽ert при отсутствии.
- Транзакции `db.commit()` после каждой операции записи.
- Закрытие курсора и соединения в конце запроса.

### C# service (`Program.cs`)
- Параметризованные запросы через ADO.NET (`MySqlCommand.Parameters`).
- Нет ORM, нет лишних абстракций.
- Конечные точки: `/health`, `/api/repositories`, `/api/links`, `/api/links/domains`.

### Фронтенд
- Верстка без зависимостей (чистый HTML/CSS/JS).
- Тёмная тема GitHub UI, нет эмодзи, градиентов, glassmorphism, анимации.
- Адаптивная сетка для мобильных.

### Что не проверялось
- Нет интеграционных тестов (добавить при необходимости).
- LLM API URL/ключ опциональны, fallback работает без них.

## 3. Выводы

Проект соответствует ТЗ: никаких секретов в коде, параметризованные запросы, прямой SQL, микросервисная структура, готов к `git push`.
